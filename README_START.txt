ТОПЛИВО56 / РАДАР БАК v0.5 — ПИЛОТ 15-МИНУТНЫХ СВОДОК В MAX
===============================================================

ВАЖНО: это обновление существующей v0.4. Оно не меняет заголовки
листов «Показания», «Сообщения» и «Подтверждения».
Никакие локальные черновики из старого приложения автоматически не публикуются.
Доставка в MAX работает ТОЛЬКО после настройки токена, получателя и запуска триггера.

Шаг 1. Сохраните резервную копию текущего Code.gs и файлов GitHub.
Шаг 2. В связанной с таблицей Google Apps Script замените Code.gs кодом
       из отдельного Toplivo56_Code_v0_5.gs. Сохраните.
Шаг 3. Настройте в «Настройки проекта -> Свойства скрипта»:
       MAX_BOT_TOKEN = реальный токен своего бота MAX
       ID_PEPPER = длинная случайная секретная строка (32+ символа)
       COMMUNITY_WRITES_ENABLED = NO (пока идёт проверка)
       DIGEST_USER_ID = ваш числовой MAX user_id (кнопка «Показать мой MAX ID» в Профиле приложения)
                 ИЛИ
       DIGEST_CHAT_ID = числовой ID чата/канала, где есть бот
       DIGEST_SEND_EMPTY = NO (не присылать пустые сводки)
       Указывайте ровно один DIGEST_USER_ID / DIGEST_CHAT_ID.
       НЕ ПИШИТЕ токен или ID_PEPPER в GitHub или в чат.
       Если ранее задан ID_PEPPER, НЕ меняйте его (иначе старые
       хешированные идентификаторы пользователей перестанут совпадать).
Шаг 4. Из редактора Apps Script выполните:
       testMaxDigestConnection
       Перед тестом откройте личный диалог с вашим ботом MAX и запустите бота.
       Если получите тестовое сообщение в MAX, соединение работает.
       Если нет — смотрите «Выполнения» и ошибки HTTP/сертификата.
Шаг 5. Выполните previewDigest15m и посмотрите текст в журнале.
Шаг 6. Выполните installDigestTrigger ОДИН РАЗ — будет один
       time-based trigger каждые 15 минут. Отправляет только
       новые сообщения за период и их новые подтверждения.
       При отсутствии событий ничего не отправляет.
       Для отключения выполните stopDigestTrigger.
Шаг 7. Для записи от водителей выполните отдельные проверки:
       проверьте правила обработки персональных данных/хранения,
       откройте мини-приложение именно в MAX, проверьте WebApp.initData,
       попробуйте записать на тестовом аккаунте.
       Только после этого установите COMMUNITY_WRITES_ENABLED=YES
       в Script Properties, и COMMUNITY_WRITES_ENABLED: true в config.js.
       При выключенном флаге приложение сохраняет ТОЛЬКО локальные черновики.
Шаг 8. Обновите ТО ЖЕ САМОЕ веб-развертывание Apps Script новой версией.
       Параметры: «Выполнять от моего имени», доступ «Все».
       Записи блокируются сервером без подписи MAX, а по умолчанию вообще отключены.
       Обычно сохраняется /exec URL. Если адрес сменился,
       обновите API_URL в config.js на актуальный адрес.
Шаг 9. Замените все файлы GitHub Pages файлами из фронтенд-архива
       v0.5. Проверяйте внутри MAX, затем жмите «Обновить данные».

ЧТО ОТПРАВЛЯЕТСЯ В MAX:
- Заголовок «РАДАР БАК | СВОДКА ПО АЗС», временное окно по Оренбургу.
- Только сообщения из листа «Сообщения» и свежие изменения голосов.
- Группировка по АЗС и виду топлива/событию.
- Отметка «ожидает», «подтверждено» (от 2 независимых голосов) или «спорно».
- Если не поступило новых данных — по умолчанию не отправляет пустое сообщение.

ОГРАНИЧЕНИЯ ПИЛОТА:
- Одна общая сводка на ОДИН настроенный user_id или chat_id. Личные
  настройки подписок внутри приложения пока только локальные.
- Сводка не гарантирует наличие топлива. Адреса каталога предварительные.
- Периодичность Google Apps Script приблизительная, не строгие 00/15/30/45.
- Google Apps Script -> MAX UrlFetchApp не тестировался с реальным токеном;
  при SSL-проблеме сертификата Минцифры может потребоваться внешний backend.
- Листы ограниченно сканируются (последние 2000 сообщений и 5000 голосов).
- После перепубликации убедитесь, что проверка подписи MAX работает.
- Изменения в Google таблице «Показания» НЕ создают водительские уведомления:
  сводка берёт только «Сообщения» / «Подтверждения».
